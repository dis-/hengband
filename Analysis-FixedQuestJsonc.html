固定クエストのJSONC移行

← 解析 / Analysis

固定クエスト（街の依頼・塔・ボス戦などの固定レイアウトを持つクエスト）の定義を、従来の固定マップテキスト（lib/edit/quests/*.txt ＋ QuestDefinitionList.txt ＋ 共通ベース凡例 QuestPreferences.txt）から、クエストごとの JSONC へ移行しました。他データ（モンスター・アーティファクト等）の JSONC 化に足並みを揃え、クエストデータを JSON Schema による検証下 に置くことが目的です。マップは文字列配列で表現し、グリッドの可読性を維持しています。

このページは移行の 仕様 と フォローアップ予定 をまとめた開発向けドキュメントです。対象PR: hengband/hengband#5486。前提として CAVE_ICKY → CAVE_NO_TELEPORT_DEST のリネームは別PR #5485 で先行実施しています（テレポート「侵入」禁止を意味し、「退出」は禁じないため名称を是正）。

JSONC の構造

{
  "version": 1,
  "id": 4,
  "name": { "ja": "宝物庫", "en": "The Vault" },
  "definition": {
    "type": "FIND_ARTIFACT",     // クエスト種別（旧 Q:Q の type）
    "level": 30,                  // 危険度（階相当）
    "flags": ["PRESET", "ONCE"],  // SILENT / PRESET / ONCE / TOWER
    "maxNum": 1,                  // KILL_LEVEL 等の討伐数
    "monster": 813,               // 討伐対象 MonraceId（KILL_LEVEL 等）
    "reward": { "artifacts": [88, 76, ...] }  // 旧 Q:R の報酬候補
  },
  "descriptions": [               // 旧 ?:[...] 条件付きテキスト
    { "when": { "statusAtMost": "COMPLETED", "questType": "FIND_ARTIFACT" },
      "text": { "ja": ["..."], "en": ["..."] } }
  ],
  "legend": {                     // このクエスト固有の記号定義（旧 F:）
    "a": { "terrain": "FLOOR", "caveInfo": ["ROOM", "NO_TELEPORT_DEST"],
           "artifact": { "questReward": true } }
  },
  "mapVariants": [ ["XXXX...", "..."], ... ],  // 1個=固定 / 複数=$RANDOMn バリアント
  "start": { "y": 17, "x": 25 }                // 開始位置（複数なら startVariants）
}
  • descriptions[].when: statusAtMost / status（＝旧 $QUESTnn のステータス比較）と questType（＝旧 $QUEST_TYPEnn）で表示ブロックを排他選択します。
  • legend: クエスト固有の記号のみ定義し、共通記号は QuestPreferences.jsonc から供給されます（各クエストマップは差分だけを持つ）。
  • mapVariants: 複数マップは $RANDOMn（下記）でキャラクター単位に決定選択されます。
  • startVariants: leavingQuest 条件で開始位置を分岐（塔の階層移動で使用）。

データモデルと生成経路

QuestReader が1つのクエスト JSONC を QuestType（実行時状態） と QuestFixedMap（静的レイアウト＝凡例・マップ・説明文・開始位置・メタデータ） に分解します。QuestFixedMapList が全クエストのレイアウトを起動時に一度だけ保持し、フロア生成やダイアログ表示から参照します（従来は表示のたびに .txt を再パースしていた経路を廃止）。

  • apply_quest_metadata(): 静的メタデータ（type/level/r_idx/… ＋ QUESTOR）を QuestType に適用。起動時・リセット時・フロア生成時に呼ばれる冪等処理。
  • resolve_quest_reward(): 報酬アーティファクトの確定・予約。受託時のみ 実行（旧 INIT_ASSIGN 相当）。
  • generate_quest_floor_from_json(): 共通ベース凡例をグローバル letter[] に読み込んだ後、クエスト固有凡例を上書きし、既存の parse_qtw_D / parse_qtw_P でセルを配置します。

挙動の要点（旧 parse_qtw_* との対応） / Behaviour parity

移行は 挙動保存 が原則で、全 definition フィールドが元の Q:Q 行とラウンドトリップします。特に注意した点：

項目 仕様 根拠
QUESTOR フラグ 全クエストの UNIQUE 討伐対象へ、起動時・リセット時に付与（apply_quest_metadata）。旧 init_dungeon_quests が birth で全クエストを INIT_ASSIGN していた挙動に一致。未受託でも対象ユニークが通常ダンジョンに漏れない MonraceAllocationTable が is_valid()（QUESTOR を除外）でフィルタ
報酬（Q:Q/Q:R） 受託時のみ resolve_quest_reward で確定。候補から未生成の1つを予約、全生成済みなら KILL_ALL へ格下げ 新規キャラ生成時の reset_all() → ArtifactRecords リセットの順で予約が消えないようにするため
type の保護 apply_quest_metadata は status==UNTAKEN または type==NONE のときのみ静的 type を適用。受託時に決まった実行時 type（KILL_ALL 格下げ等）をフロア再生成で戻さない —
マップバリアント選択 $RANDOMn は seed_town % n（キャラクター固定・スカミング対策）。mapVariants は AngbandSystem::get_seed_town() % 個数 で選ぶ。宝物庫の報酬部屋が毎回同じなのは仕様 AngbandSystem::get_seed_town()
ベース凡例のランダムセル 9=モンスター(ood9)+物品(ood7) / @=モンスター(ood11) / *=物品+罠 / T=物品。旧 F: の *N を {random, oodLevel: N} で表現し、同一の grid テンプレートを生成 general-parser.cpp の *N 解釈と一致

ロード時の防御 / Loader validation

  • 重複 ID の拒否: JSON Schema は「ファイル横断の一意性」を表現できないため、load_json_quests が重複 id を検出して起動時にエラー（見逃すと2ファイルが同一エントリへ追記され、偽のマップバリアント化等の破損を起こす）。
  • データ欠落の fail-fast: lib/edit/quests ディレクトリや .jsonc が無い場合、後続の get_quest() クラッシュではなく起動時に明確なエラーで停止。
  • マップ寸法の上限: スキーマの mapRows に maxItems: 66（＝MAX_HGT）／行 maxLength: 198（＝MAX_WID）を設定。過大なマップがフロア生成で領域外書き込みを起こす経路を検証層で遮断（本リポジトリは JSON Schema をデータ検証層 として運用）。
