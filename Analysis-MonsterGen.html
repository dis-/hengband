モンスター生成

← 解析 / Analysis

概要

モンスターは (1) フロア生成時の初期配置 と (2) 探索中の継続スポーン（画面外での自然湧き）の2経路で生成される。どのモンスターが出るかは基本的に 現在の階（dun_level） で決まり、ゲーム内経過日数に応じて格上（階層外＝out-of-depth, OOD）モンスターが混じるようになる。

フロア生成時の初期配置

cave-generator.cpp がフロア生成の最後に配置数を決める。

配置数 = ダンジョンの min_monster_count_on_floor
配置数 = 配置数 × (フロア高 / MAX_HGT) × (フロア幅 / MAX_WID) + 1   （小さい階は減る。上限は元の値）
配置数 += randint1(8)

この回数だけ alloc_monster() を呼んで配置する（アイテム配置数も加算してループ）。

探索中の継続スポーン

decide_alloc_monster()（src/world/world-turn-processor.cpp）が毎ゲームターン判定する。

  • one_in_(ダンジョンの additional_monster_spawn_chance) を引くと、画面外（プレイヤーから視界+5マス以遠）に1体 を alloc_monster で配置する。
  • アリーナ内・クエスト内・phase out 中は湧かない。
  • 湧き頻度はダンジョンごとの additional_monster_spawn_chance（値が小さいほど頻繁）に依存する。

配置位置の決定（alloc_monster）

  1. 最下層の固定守護者（final_guardian）が未討伐でその階なら最深部に配置。
  2. プレイヤーから距離が (min_dis, max_dis] に入るランダムな空きグリッドを最大10000回試行して探す。
  3. randint1(5000) <= 階 の確率（＝階/5000）で モンスターの大群（horde） を発生させる（詳細は後述「モンスターの大群（horde）」）。深い階ほど群れが出やすい。
  4. それ以外は place_random_monster（グループ生成を許可）で1体（＋グループ）配置。

どのモンスターが出るか（get_mon_num）

get_mon_num()（src/monster/monster-list.cpp）が階層に応じて抽選する。基準となる max_level は原則その階（dun_level）。

経過日数による階層外（OOD）モンスターの深化

長時間プレイするほど、現在の階より深いモンスターが混じるようになる（「nasty」生成）。

  • 基準日: delay = √(max_level×10000) + max_level×5 から算出。深い階ほど基準日が遅い。目安は 1F=約5日 / 10F=約18日 / 30F=約34日 / 60F=約53日 / 90F=約69日。
  • 経過日数 over_days = max(0, 経過日数 − 基準日)。
  • OOD発生確率 chance_nasty = max(3, 25 − over_days/2)。基準日直後は 1/25、約44日後に上限 1/3 まで上がる。
  • 発生時、max_level を nasty_level = min(25, over_days/3) だけ引き上げる（+0 から約75日後に +25 まで）。
  • 迷路ダンジョン（MAZE）は nasty 確率が上がり max_level +3。
  • 悪夢モード（ironman_nightmare）はさらに大きく OOD 化する（max_level = 1 + max_level×MAX_DEPTH/randint1(MAX_DEPTH)）。

抽選

  • アロケーションテーブルから、min_level ≤ 種族レベル ≤ max_level の種族を出現確率 prob2 で重み付け抽選。
  • 除外されるもの: 討伐済みユニーク（分離ユニークは別個体を選択）、生成不可、ONLY_ONE で既に場にいる種族、選択不可種族など。
  • 多重抽選で深いモンスターに偏る: 40% で1回・50% で2回・10% で3回抽選し、その中で 最もレベルの高い モンスターを採用する。

特殊な部屋・ヴォールトによる格上（OOD）モンスター

前述の「経過日数によるOOD化」とは別に、特定の部屋・巣・巣窟・ヴォールトの中では、その位置に配置するモンスターの生成レベル（get_mon_num に渡す max_level）を一時的に 現在の階より引き上げて 抽選する。これにより、階層より深いモンスターがまとまって出現する。以下がその全一覧である。

生成場所 生成レベル 補足
モンスターの巣（nest） 階 + 11 64 匹を階+11で選抜。テーマ（同種クローン/同シンボル）は 階 + 10 で選んだ基準モンスターに合わせる
モンスターの巣窟（pit・標準） 階 + 11 候補をレベル順に整列し、強い個体を中心付近に配置する
トラップの巣窟（trapped pit） 階 + 0 巣窟だが格上補正は無し（現在の階基準）
固定ヴォールト 記号 & 階 + 5 通常のヴォールト内モンスター（グループ可）
固定ヴォールト 記号 @（Meaner monster） 階 + 11 やや強いモンスター
固定ヴォールト 記号 9（Meaner ＋宝） 階 + 9 ＋アイテム（生成レベル 階 + 7, AM_GOOD）
固定ヴォールト 記号 8（Nasty monster ＋宝） 階 + 40 ＋高級アイテム（生成レベル 階 + 20, AM_GOOD|AM_GREAT）
固定ヴォールト 記号 , 1/2 の確率で 階 + 3 1/2 でアイテム（階 + 7）も
ランダム／迷路ヴォールトの空きマス充填（fill_treasure） 中心に近いほど 階 + 40 / 階 + 20 / 階 + 9 / 階 + 5 / 階 + 3 中心からの距離で難度が決まり、中心ほど格上（階 + 40 は最深）。外周寄りは通常/罠/アイテム
内部にヴォールトを持つ部屋（十字部屋・内壁部屋・円形部屋など）の vault_monsters 階 + 2 部屋中央の宝物区画に少数配置

補足:

  • 上記の引き上げは get_mon_num の max_level を高めるだけなので、「抽選」の多重抽選（40/50/10 で最深を採用）や、経過日数によるOOD化も重ねて効く。実際の個体は表の値より更に深くなりうる。
  • 引き上げ後もユニークの討伐済み判定・生成可否などの通常の除外は同様に適用される。
  • 階 は正確には base_level（通常は dun_level と同じ）。処理中だけ monster_level を書き換え、直後に元へ戻す。
  • ヴォールト・巣・巣窟自体の出現条件（階層・確率・部屋数）は 特殊部屋生成 を参照。

グループ・大群の頭数（place_monster_group）

群れを作るモンスターは複数体で出現する。

extra = 0
種族レベル < 階 なら  extra = +randint1(階 − 種族レベル)
種族レベル > 階 なら  extra = −randint1(種族レベル − 階)
extra は ±9 で頭打ち
頭数 = randint1(10) + extra   （1〜32体にクランプ）

中心の周囲へ散布して配置する。格下（階より浅い）モンスターほど大群になりやすい。

モンスターの大群（horde）

alloc_horde()（src/monster-floor/monster-generator.cpp）による特別な大量発生。前述のとおり配置1回ごとに randint1(5000) <= 階 の確率（＝階/5000、深い階ほど頻繁）で発生し、同じシンボル（種別文字）のモンスターが一箇所に大量に湧く。

頭目（リーダー）の選抜

select_horde_leader_r_idx() が、通常の get_mon_num(max_level = monster_level) で頭目を1体選ぶ（最大1000回試行）。次は頭目になれない:

  • ユニークモンスター（UNIQUE）
  • HAGURE（はぐれもの）

選んだ頭目を配置地点に置く（最大1000回試行）。

群れ本体の召喚

頭目を中心に、randint1(10) + 5 回（＝ 6〜15 回）の召喚を行う。各召喚は:

  • summon_specific(..., 階 + 5, SUMMON_KIN, PM_ALLOW_GROUP, 頭目) を呼ぶ。ただし summon_specific（src/monster-floor/monster-summon.cpp）は渡された lev をそのまま使わず、内部で max_level = (現在階 + lev) / 2 + 5 に再計算する。ここでは lev = 階+5 なので 実効生成レベル = (階 + (階+5))/2 + 5 ＝ 階 + 7（例: 60F なら 67）。頭目（階）より深いモンスターまで混じりうる。
  • SUMMON_KIN＝頭目と同じシンボル文字のモンスターのみを呼ぶ（HAGURE は対象外）。このため大群は「同じ記号のモンスターの集団」になる（例: o ならオーク系ばかり）。
  • PM_ALLOW_GROUP 付きなので、召喚された各個体がさらに自分のグループを伴うことがある（雪だるま式に増える）。
  • 散布中心は毎回 直前に召喚した位置へ移動する（pos = pos_scat）。半径5以内へ順に撒くため、群れは一方向へ帯状に広がる傾向がある。

補足

  • 頭目選抜は get_mon_num(monster_level)＝階まで。群れ本体は召喚レベルの平均化により 実効 階 + 7 まで（上記）。格上補正が乗るため、大群本体は頭目より深いモンスターを含む。例えば 60F・day8（経過日数OODが効かない早期）でも、D の大群本体には Lv67（＝階+7）の「カオス・ワイアーム」等が出うる。
  • 大群は「同一シンボル」で構成されるが、SUMMON_KIN はレベル条件も満たす種族から選ぶので、同記号でも複数種が混ざりうる。
  • cheat_hear（デバッグ）時のみ「モンスターの大群(記号)」というメッセージが出る。
  • 頭目がカメレオンの場合、メッセージには変身後の記号が使われる。

護衛・分隊・変装（place_specific_monster）

  • グループ許可時、種族が持つ 護衛（reinforce） や 分隊（ESCORT フラグ） のモンスターを周囲に配置する。
  • one_in_(333) で 影による変装体（kage） になる（PM_NO_KAGE 指定時は抑止）。

生成直後の状態（place_monster_one）

  • 睡眠: PM_ALLOW_SLEEP かつ種族の sleep > 0 かつ非悪夢モードのとき、csleep = sleep×2 + randint1(sleep×10) で 眠った状態 で出現する。悪夢モードでは常に起きている。
  • 個体ごとの速度変動（set_individual_speed）: 非ユニークかつアリーナ外で生成された個体は、速度がわずかに変動する。ユニークおよびアリーナ内では種族の基本速度のまま変動しない。
    • 変動幅 i = speed_to_energy(基本速度) / (1/4 の確率で 3、残り 3/4 は 10)。speed_to_energy は加速内部値（標準 = 110、→ 加速内部値）を 1 ターンの行動エネルギーへ変換する値で、標準 110 で 10、以降 +10 ごとに概ね +10 増える。
    • 個体の速度は 基本速度 + rand_spread(0, i)。rand_spread(0, i) は [-i, +i] の一様乱数（平均 0）なので、速くも遅くもなりうるが平均は基本速度どおり。結果は上限 110 + 99（内部値 209）にクランプされる。
    • 例: 基本速度が標準 110（speed_to_energy = 10）なら、3/4 で i = 1（±1）、1/4 で i = 3（±3）。基本速度が速い個体ほど変動幅も大きく（例: 速度 130 は speed_to_energy = 30 で ±3〜±10）、逆に speed_to_energy < 10 の低速種族は 3/4 の場合 i = 0 となり変動しないこともある。
  • ユニークは max_num（多くは1体）まで。討伐済みユニークは再生成されない。

まとめ

  • 出現モンスターは基本「現在の階」で決まるが、プレイ日数が経つほど格上（OOD）が混じる（最大 +25 階相当、確率最大 1/3）。
  • 多重抽選により、同じ階でも やや深いモンスターへ偏る。
  • 巣・巣窟・ヴォールト（特殊部屋）の中では生成レベルが引き上げられ、階より深いモンスターがまとまって出る（巣/巣窟は 階 + 11、ヴォールト記号 8 は最大 階 + 40）。
  • 群れ・護衛・大群により、1回の生成で複数体まとまって出ることがある。
  • 生成時は種族の sleep に応じて眠っていることが多い（悪夢モードを除く）。
