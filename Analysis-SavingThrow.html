魔法防御

← 解析 / Analysis

魔法防御（セービングスロー）とは

「魔法防御」は、プレイヤーが受ける状態異常・精神攻撃・呪殺系の魔法効果に対する抵抗判定に用いられる能力値である。内部的には skill_sav（セービングスロー値）という単一の整数で表現され、ステータス画面では「魔法防御」として表示される。

ここでは (1) skill_sav の算出式、(2) それを用いた抵抗成功判定の式、(3) 逆に「プレイヤーが放った魔法にモンスターが抵抗する」側の判定、の3つを扱う。

skill_sav の算出式

skill_sav は calc_saving_throw()（src/player/player-status.cpp）で毎回再計算される。処理を順に追うと次のとおり。

pow = 種族のr_sav + 職業のc_sav + 性格のa_sav
pow += (職業のx_sav * レベル / 10) + (性格のa_sav_2 * レベル / 50)
       ※コード上は (cp_ptr->x_sav * lev / 10) + (ap_ptr->a_sav * lev / 50)

// 変異：魔法防御(MAGIC_RES)を持つ場合
if 魔法防御の変異あり: pow += 15 + (レベル / 5)

// 装備：呪力耐性(resist_curse)がある場合
if 呪力耐性あり: pow += 30

// 祝福された武器(bless_blade)を装備している場合
if bless_blade: pow += 6 + (レベル - 1) / 10

// 賢さ(WIS)による加算
pow += adj_wis_sav[WISの内部インデックス]

// 呪いの弱点(vuln_curse)による減算
if 呪力弱点あり:      pow -= 10
if 強力な呪力弱点あり: pow -= 20

// 狂戦士化(shero)による減算
if 狂戦士化: pow -= 30

// 反魔法(anti_magic)状態の下限保証
if 反魔法状態 かつ pow < 90 + レベル: pow = 90 + レベル

// クターの「つぶれ」状態(tsubureru)による上書き
if tsubureru: pow = 10

// 「魔法防御(magicdef)」「レジストマジック(resist_magic)」
// 「究極の耐性(ult_res)」いずれかの下限保証
if (ult_res または resist_magic または magicdef) かつ pow < 95 + レベル:
    pow = 95 + レベル

// 呪いのdown_saving（セービングスロー低下）
if down_saving: pow /= 2

return pow

各寄与要素の意味

  • 種族 r_sav／職業 c_sav／性格 a_sav: それぞれの固定基礎値。ミミック（変身）中は種族値の代わりに変身先の値を用いる。
  • 職業レベルボーナス x_sav * lev / 10: レベルに比例して伸びる主要素。職業ごとの x_sav の大小が、レベルが上がったときの魔法防御の伸びを決める。
  • 性格レベルボーナス a_sav * lev / 50: 性格の a_sav に基づく、より緩やかなレベル比例加算。
  • 賢さボーナス adj_wis_sav[]: WIS が高いほど大きくなる。テーブル値（src/player/player-status-table.cpp）は次のとおり。
WIS 3〜7      : +0
WIS 8〜14     : +1
WIS 15〜17    : +2
WIS 18〜18/49 : +3
WIS 18/50〜18/69 : +4
WIS 18/70〜18/89 : +5
WIS 18/90〜18/99 : +6
WIS 18/100    : +7
WIS 18/110    : +8
WIS 18/120    : +9
WIS 18/130    : +10
… 以降 18/220+ の +19 まで、10刻みで+1ずつ増加

上書き・下限保証の優先順位

算出式の末尾では、状態に応じた「上書き」「下限保証」が順に適用される。適用順そのものが結果に影響するため、コード上の順序どおりに列挙する。

  1. 反魔法(anti_magic): pow が 90 + レベル 未満ならその値まで引き上げる（下限保証）。
  2. つぶれ(tsubureru、クター専用): 無条件に pow = 10 に固定（前段の反魔法保証すら上書きされる）。
  3. 魔法防御/レジストマジック/究極の耐性: pow が 95 + レベル 未満ならその値まで引き上げる（下限保証。つぶれによる10も、条件を満たせばここで引き上げられる）。
  4. down_saving（呪いによるセービングスロー低下）: 最後に pow を半減する。上記の下限保証で引き上げた値も、ここで半分になる。

skill_sav に明示的な上限（キャップ）は calc_saving_throw() 内には存在しない。値は各寄与要素の合計と下限保証によって決まる。

プレイヤーの抵抗成功判定

算出された skill_sav は、状態異常・精神攻撃などを受けたときの抵抗判定に使われる。判定式は Hengband 全体でほぼ統一されており、次の形をとる。

抵抗成功 ⇔ randint0(100 + rlev / 2) < skill_sav
  • randint0(N) は 0 以上 N 未満の一様乱数。
  • rlev は効果を及ぼしてくるモンスターのレベル（monrace.level）。攻撃元モンスターのレベルが高いほど判定の乱数上限 100 + rlev/2 が大きくなり、抵抗が難しくなる。
  • 左辺が skill_sav を下回れば抵抗成功。したがっておおよその抵抗成功率は skill_sav / (100 + rlev/2)（skill_sav が上限を超える場合は事実上100%）となる。

この共通式は、たとえば次の箇所で用いられている。

  • モンスターの打撃による状態異常（恐怖・混乱など）: src/monster-attack/monster-attack-status.cpp
  • モンスター呪文による状態異常（恐怖・盲目・混乱・麻痺・記憶消去など）: src/mspell/mspell-status.cpp
  • 呪い攻撃 effect_player_curse_*（秘孔を突く等）: src/effect/effect-player-curse.cpp
  • 破滅の手(hand of doom): src/effect/effect-player-resist-hurt.cpp

精神攻撃での下限補正

精神攻撃系（effect_player_mind_blast / effect_player_brain_smash、src/effect/effect-player-spirit.cpp）では、判定に用いる値が skill_sav そのものではなく max(5, skill_sav) となっている。すなわち skill_sav がどれほど低くても、これらに対しては最低5相当の抵抗力が保証される。

抵抗成功 ⇔ randint0(100 + rlev / 2) < max(5, skill_sav)

ブレインスマッシュによる能力値低下も、同じ max(5, skill_sav) を用いた判定を能力値ごとに繰り返す形で処理される。

幻影(multishadow)による無効化

分身（multishadow、幻影）状態のときは、多くの精神攻撃・呪い判定で !check_multishadow(player_ptr) が条件に加わり、分身中は抵抗判定の成否に関わらず効果自体が回避される（攻撃が幻影に当たる扱い）。

PSI（超能力）の反射判定

src/effect/effect-monster-psi.cpp では、モンスターへの PSI 攻撃がプレイヤーに跳ね返ってくる際の反射判定にも同じ形式が使われる。

反射成功 ⇔ randint0(100 + monrace.level / 2) < skill_sav

モンスター側の抵抗判定（プレイヤーの魔法に対して）

プレイヤーが放った状態異常・魅了系の魔法にモンスターが抵抗するかどうかは、プレイヤー側の skill_sav とは無関係で、モンスターのレベル対効果パワーの対抗ロールで決まる。式の形はプレイヤー側とは異なる。

恐怖・混乱・テレポート等の一般式

src/effect/effect-monster-evil.cpp や effect-monster-charm.cpp に見られる代表的な式は次のとおり。

抵抗成功 ⇔ monrace.level > randint1(max(1, dam - 10)) + 10
  • dam は効果の強さ（パワー）。
  • randint1(N) は 1 以上 N 以下の一様乱数。
  • モンスターのレベルが、パワー由来の乱数値を上回れば抵抗成功。パワー dam が大きいほど右辺の乱数上限が上がり、抵抗されにくくなる。

テレポート抵抗のように、単純に monrace.level > randint1(100) を用いる箇所もある。

魅了・服従の共通式

魅了(common_saving_throw_charm)・服従(common_saving_throw_control)のセービングスローは src/spell/spells-diceroll.cpp に共通化されている。前提となる無効化条件（アリーナ内、RESIST_ALL、NO_CONF、クエストモンスター、NOPET フラグ等）を満たすと無条件で抵抗成功となり、それ以外では次の式を用いる。

pow += adj_chr_chm[CHRの内部インデックス] - 1        // 魅力(CHR)ボーナス
if モンスターがユニーク または ナズグル: pow = pow * 2 / 3   // 抵抗されやすくなる
抵抗成功 ⇔ monrace.level > randint1(max(1, pow - 10)) + 5

ここでのパワー pow は術者(プレイヤー)の魅力(CHR)によって補正され、対象がユニーク／ナズグルの場合はパワーが2/3に減じられ、抵抗されやすくなる。

混乱付与時の追加抵抗

魅了とは別に、モンスターへ混乱を付与する処理では、ユニーク・クエスト・混乱耐性(NO_CONF)持ちに加えて、

monrace.level > randint1(max(1, dam - 10)) + 10

を満たす場合にも混乱が無効化される（src/effect/effect-monster-charm.cpp）。

まとめ

  • プレイヤーの魔法防御は単一値 skill_sav に集約され、種族・職業・性格の基礎値、職業/性格のレベル比例ボーナス、賢さ(WIS)、装備・変異・一時効果（反魔法・レジストマジック・魔法防御・呪力耐性・狂戦士化・呪い等）で増減する。
  • 抵抗判定はプレイヤー側では randint0(100 + rlev/2) < skill_sav という一貫した式で行われ、相手モンスターのレベルが高いほど抵抗が難しくなる。精神攻撃では最低5の下限、分身時は判定を経ずに無効化される。
  • 逆にプレイヤーの魔法に対するモンスターの抵抗は、プレイヤーの skill_sav ではなく「モンスターレベル対効果パワー」の対抗ロール（monrace.level > randint1(...) + 定数）で判定され、魅了・服従では術者の魅力(CHR)とユニーク/ナズグル補正が加わる。

（本解説の数値・式はいずれも現行ソース src/player/player-status.cpp ほか上掲ファイルの実装から直接確認したものである。）
