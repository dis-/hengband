AGENTS.md — 変愚蛮怒 Wiki / Pages 生成リポジトリ

エージェント（codex / Claude 等）向けの入口ドキュメント。運用の詳細手順は tools/README.md を参照。ここには 全体像・不変規則・ ソースから導出した知識・再生成の地雷 をまとめる。

Entry doc for coding agents. Operational how-to is in tools/README.md; this file holds the big picture, invariants, source-derived knowledge, and gotchas.

これは何か / What this repo is

このリポジトリは dis-/hengband の GitHub Wiki（dis-/hengband.wiki.git）であり、 同時に GitHub Pages サイト https://dis-.github.io/hengband/ の生成元でもある。

  • 日英併記（bilingual JA/EN）のゲームデータ・リファレンスを、変愚蛮怒本体の lib/edit/*.jsonc（データの正）と src/**/*.cpp（挙動の正）から決定的に自動生成する。
  • 2出力・同一ソース： (1) Wiki（master の *.md）、(2) Pages（dis-/hengband の gh-pages ブランチの *.html）。どちらも tools/ のスクリプトが吐く。
  • 表の中身は手入力ではなくデータ由来。データ更新後に再生成すれば全ページが最新化される。

リポジトリ構成とパス / Repos & paths

チェックアウトは使い捨てで良い（セッションの scratchpad に fresh clone すれば数秒）。 build-site.mjs の --wiki 既定値はスクリプト自身が入っている repo（tools/..）を指すので 常に正しく、--out は必須引数（未指定はエラー終了）——古い既定パスへ誤ビルドする地雷は撤去済み。

対象 場所 役割
Wiki（この repo, master） 任意（fresh clone 可） 生成された *.md＋生成ツール（tools/）
Pages（gh-pages） 任意（fresh clone 可） build-site.mjs が吐く *.html（≈1880ページ）
本体ソース C:/hengband lib/edit/*.jsonc＝データ、src/**/*.cpp＝挙動。生成の --src 既定は C:/hengband/lib/edit
Node マシン依存 まず node --version を試す（PATH にあることが多い）。無ければ携帯版等をフルパスで
  • Wiki リモート: https://github.com/dis-/hengband.wiki.git
  • Pages リモート: https://github.com/dis-/hengband.git（gh-pages ブランチのみ。master＝ゲーム本体には触れない）
  • シェルは PowerShell が主だが、gh api 等では Git Bash＋MSYS_NO_PATHCONV=1 を使う。

古いクローンを使い回す場合はコミット前に git -C <dir> ls-remote origin <branch> で HEAD がリモートと一致することだけ確認する（遅れていれば pull / reset で追従）。

セットアップ（fresh clone）:

git clone git@github.com:dis-/hengband.wiki.git <wikirepo>
git clone -b gh-pages --single-branch git@github.com:dis-/hengband.git <ghp>
cd <wikirepo> && npm i markdown-it        # build-site 用

生成・ビルド・公開 / Regenerate, build, publish

cd <wikirepo>
node tools/generate-wiki.mjs                 # 1) Wiki md 再生成（--src 省略時 C:/hengband/lib/edit）
node tools/build-site.mjs --out=<ghp>        # 2) Pages HTML ビルド（--wiki は自 repo が既定）
# 3) 公開（write-if-changed により差分＝実変更。両側とも add -A で安全）
git add -A && git commit && git push origin master
git -C <ghp> add -A && git -C <ghp> commit && git -C <ghp> push origin gh-pages

検証はビルド後に grep -rl '<em>' <ghp>/*.html | wc -l が 0 であることを確認（絶対規則4）。

依存は npm i markdown-it（build-site 用、node_modules は gitignore）。 kuromoji（読み再生成）は通常不要。詳細・列設計・specs.json・SVGタイルは tools/README.md 参照。

絶対規則 / Invariants（破ると自動生成物が壊れる）

  1. 生成された *.md / *.html を手編集しない — 再生成で上書きされる。
    • 表の内容を変えたい → 本体 lib/edit/*.jsonc を編集。
    • 体裁・ラベルを変えたい → tools/generate-wiki.mjs / tools/specs.json。
    • 呪文の詳細効果を変えたい → tools/spell-effects.json（下記）。
    • 解析ページ本文 → tools/analysis/Analysis-<Slug>.md（生Markdown、< > はそのまま）。
  2. GFM テーブルのセル内の | は必ず \| にエスケープ（コード span 内でも）。壊れると列数不一致。 検証: scratchpad/validate-tables.mjs（列数ミスマッチ 0 を維持）。
  3. Wiki 内でシンボルはインラインSVG/CSS/data: を使わない（GitHub が除去する）。 コミット済み SVG を <img src="https://raw.githubusercontent.com/wiki/<owner>/<repo>/images/..."> で参照する。
  4. esc()（generate-wiki.mjs）は * もエスケープする。ゲーム内名称の *解呪* *鑑定* 等が イタリック化しないため。データ側（jsonc / spell-effects.json / analysis 本文）には生の * を そのまま書いてよい（テーブルセル経由なら自動エスケープ、コードブロック内は不要）。 esc() を通らない経路（bothOf 直など）で * 入り文字列をセルに入れるときは esc() で包む。 検証: ビルド後 grep -rl '<em>' <ghp>/*.html | wc -l が 0 であること。
  5. 解析ページの追加 = モジュールスコープの ANALYSIS 配列に1エントリ（cat: combat/monster/chara/item/system）＋ tools/analysis/<file>.md 本文。解析インデックスと サイドバーは同じ ANALYSIS 配列から自動生成される（手で _Sidebar を編集しない）。 検索インデックス（Pages 左上）も全ページのタイトルを自動収載する。 解析本文に <!--GEN:name--> だけの行を書くと、ANALYSIS_TABLES[name]() が返す生成表に 置換される（buildAnalysis の readBody）。データ由来の表を解析ページに載せたいときは 本文へ表を手書きせず、この仕組みで生成すること。現在の name: class-skill-caps（職業× 素手/二刀流/乗馬/盾の開始・上限ランク）、class-weapon-caps（職業×武器分類の内訳）。 検索インデックスはページ見出し（ja）を収載するので、利用者が検索しそうな語を題に含める （例: 「技能」だけでは「熟練度」で引けなかったため「技能・熟練度」に改題）。

呪文の詳細効果 tools/spell-effects.json（ソース導出・重要）

  • キー = "REALM|spell_tag" → 値 = 日本語の詳細効果文。Spell-<領域> ページの 「詳細効果（ソース準拠）」列に入る。全13領域416件済み。
  • 導出規則: spell_id は do_<realm>_spell(player_ptr, spell, mode) の case 番号。 mode==INFO がダイス式（info_damage/info_duration 等）、mode==CAST が実効果。Lv = plev。 仕様変更時は該当領域の do_<realm>_spell の当該 case を読み直して JSON を編集する。

呪文キー ソース関数（ファイル） 要点
CHAOS|Wonder cast_wonder（src/spell-kind/spells-random.cpp） die=1d100+Lv/5（幸運の徳で増減）。低目=増殖/加速/敵回復など無害〜逆効果、高目=地震/破壊/退散

召喚呪文の敵対可能性・条件（PM_FORCE_PET/PM_NO_PET から導出）

  • 常に味方（敵対なし） = PM_FORCE_PET 直、または詠唱成功時のみ実行： 精霊召喚(Arcane)・動物召喚(Nature)・ゴーレム(Craft)・マーネス/上級デーモン(Demon, 死体生贄)・ 幻霊/古代ドラゴン(Trump, if(cast)のみ)・死体復活系（下記 ANIM_DEAD）。
  • 詠唱失敗で敵対 = trump_summoning(player_ptr, n, !fail, …) を if (cast || fail) で呼ぶ Trump 召喚全般 （成功=PM_FORCE_PET味方／失敗=PM_NO_PET敵対）。src/realm/realm-trump.cpp + src/spell/spells-summon.cpp:50。
  • 確率で敵対：
    • cast_summon_demon（pet=!one_in_(3)）→ 2/3味方・1/3敵対（Chaos/Demon の悪魔召喚）
    • cast_summon_undead（pet=one_in_(3)）→ 1/3味方・2/3敵対（Death 死者復活。敵対時ユニーク可、Lv48+で上級）
    • Crusade 天使召喚（pet=!one_in_(3), src/realm/realm-crusade.cpp）→ 2/3味方・1/3敵対
  • ANIM_DEAD（src/effect/effect-item.cpp の AttributeType::ANIM_DEAD）：プレイヤー詠唱なら PM_FORCE_PET＝常に味方。 死体は約80%、骨格は約60%で復活。Death「死体復活」/Music「フィリエルの歌」/Hex「死者復活」が該当。

⚠️ CRUSADE|Summon_Angel は既に敵対情報あり（2/3味方）＝再編集不要、という具合に既存記述を確認してから触ること。

タイムスタンプの扱い / Page stamps（2026-07-09 以降は自動で安全）

generate-wiki.mjs は write-if-changed：生成 / Generated: 行を除いて内容が既存ファイルと 同一なら書き込まず、旧ファイル（旧スタンプ）を温存する。スタンプの意味は「そのページの内容が 最後に実変更された日時」。build-site.mjs は独自スタンプを持たない純関数（md→HTML）なので、 md が変わらなければ HTML も変わらない。

したがって 再生成・再ビルド後の git status の差分＝実変更そのものであり、 両リポジトリとも git add -A で常に安全にコミットできる。旧手順（numstat 1/1 判別や awk による Generated: 行フィルタ＋選別 checkout）は不要になった。

歴史的経緯: かつては両方のスクリプトが毎回全ページに壁時計を書き込み、再生成のたび 約1840ファイルに時刻1行だけの差分が出た。その選別作業で退行を3件出荷した末、 2026-07-09 に write-if-changed 化して問題自体を除去した。

並行エージェント運用 / Concurrency（別セッションが同時編集する前提）

  • Wiki push は通常 fast-forward。reject 時は git -c rebase.autoStash=true pull --rebase origin master してから再push（リトライループ）。
  • gh-pages push は「git fetch && git reset --hard origin/gh-pages → 再ビルド → add -A → push」を reject 時に繰り返す（build-site は wiki から決定的に生成されるので、最新wikiでビルドした側が勝てば内容は正しい）。
  • generate-wiki.mjs は書き込みのみ（削除しない）。他セッションが足した新規ページ（Races/Analysis/Guide 等）は 再生成しても消えない。reset --hard origin/… で相手の最新を取り込んでから自分の変更を再適用すること。

固有名詞の裏取り / Terminology accuracy（要注意）

サブエージェントは日本語の固有名詞を捏造する。必ずソースで確認する： 職業名→src/player-info/class-info.cpp（例: 剣術家≠侍、スペルマスター≠ソーサラー、魔道具術師≠マジックイーター）、 構え→src/mind/stances-table.cpp、プレイヤーTR_REGEN=急速回復 だがモンスター lore の REGENERATE=再生（文脈で語が違う）。
