職業魔法の得意さの段階（仮仕様）

← 解析 / Analysis

⚠️ 仮仕様（検討中）。本家への提案前の設計案で、数値も含めて変わる可能性があります。

目的

現行の lib/edit/ClassMagicDefinitions.jsonc は、職業×領域×魔法ごとに習得レベル・消費MP・難易度・初回経験値倍率の 4 値を 手で書いています（14 職業 × 最大 10 領域 × 32 魔法 = 2,784 行、約 11,000 個の数値）。魔法を 1 つ追加・調整するたびに 全職業分を直す必要があります。

これを次の 2 つに分け、職業別の値はゲームの読み込み時に計算します。

  • 魔法の基準表: SpellDefinitions.jsonc の各魔法に基準値 4 つ（習得レベル・消費MP・難易度・初回経験値倍率）を持たせる。 値はメイジの現行値。歌・武芸・呪術（現在はソースに固定の technic_info）も同じ形で基準表に移す。
  • 得意さの段階: 職業×領域に「得意さの段階」を整数で 1 つ書く。0 がメイジ相当、正が得意、負が不得意。 段階から値を導く式は 1 つで、傾き 3 つだけを持つ（段階ごとの表は持たない）。意図のある例外は、習得不可の指定と、魔法ごとの段階で書く。

データ形式

ClassMagicDefinitions.jsonc は、ルートの傾き（aptitude_steps）と、職業ごとの領域の要素（段階と例外）になります。 職業単位の項目（spell_type、magic_status、first_spell_level など）は変わりません。

{
  "version": 2.0,
  // 段階 1 つあたりの動き
  "aptitude_steps": { "learn_level_percent": 30, "mana_cost_percent": 15, "difficulty": 3 },
  "classes": [
    {
      "name": "PRIEST",
      "spell_type": "LIFE",
      // ... 職業単位の項目は今のまま ...
      "realms": [
        { "name": "LIFE", "aptitude": 2, "aptitude_as_second": 1 },   // 第一領域なら +2、第二領域なら +1
        { "name": "SORCERY", "aptitude": -1 },
        { "name": "CRUSADE", "aptitude": 1, "aptitude_as_second": 0 },
        // ...
      ],
    },
    {
      "name": "RED_MAGE",
      // ...
      "realms": [
        { "name": "LIFE", "aptitude": -2, "max_book": 2 },              // 2 冊目まで
        { "name": "ARCANE", "aptitude": -1 },
        // ...
      ],
    },
    {
      "name": "TOURIST",
      // ...
      "realms": [
        {
          "name": "ARCANE",
          "aptitude": -1,
          "unlearnable": ["Zap", "Cure_Light_Wounds" /* ... */],        // 習得不可の魔法
          "overrides": [{ "spell_tag": "Identify", "aptitude": 3 }],    // この魔法だけ別の段階
        },
      ],
    },
  ],
}
項目 意味 省略時
aptitude 得意さの段階（整数。正が得意、負が不得意） 0
aptitude_as_second その領域を第二領域として選んだときの段階（第一にも第二にも選べる職業だけ） aptitude と同じ
max_book 習得できる巻数（1〜4） 4
unlearnable 習得不可の魔法の一覧 なし
overrides 魔法ごとの段階（spell_tag と aptitude） なし

SpellDefinitions.jsonc の各魔法には、基準値の 4 項目（learn_level / mana_cost / difficulty / first_cast_exp_rate）を足します。

導出の式

整数演算です。L・M・D は aptitude_steps の 3 つ、a はその魔法に使う段階（魔法ごとの段階があればそれ、無ければ領域の段階）。

book = spell_id / 8 + 1

book > max_book、または unlearnable にある → 習得不可（99 / 0 / 0 / 0）
それ以外:
  動き        = 四捨五入(基準 × (50 − 基準) × L × a / 5000)      // 基準は基準表の learn_level。符号つき（0 から遠い側へ丸める）
  learn_level = clamp(基準 − 動き, 1, 50)
  mana_cost   = max(1, 四捨五入(基準 × (100 − M × a) / 100))
  difficulty  = clamp(基準 − D × a, 0, 100)
  first_cast_exp_rate = 基準のまま
  • 習得レベルは「基準 × (50 − 基準)/50 × (30 × 段階)%」だけ動きます。基準が 25 のとき最も大きく動き、1 や 50 に近いほど小さくなります。 このため、不得意な職業でも高位の魔法がレベル 50 に張り付きにくく、巻ごとの倍率のような特例が要りません。
  • 第二領域用の表では、aptitude の代わりに aptitude_as_second を使います。読み込み時に第一用・第二用の 2 表を作り、引くときに位置で選びます。
  • 魔法ごとの段階は、第一用・第二用の両方の表に効きます。

  • 全体では 3,008 行（2,880 行にプリーストの第二領域の 128 行を加えたもの）のうち 2,034 行が変わり、 大きな変化（習得レベル ±3 以上、消費MP 25% 以上かつ差 3 以上、難易度 ±10 以上のどれか）を含む行は 1,001 です （第一領域の表だけなら 930）。

  • スペルマスターは破邪の 2 行だけメイジと違うのを、メイジの値に揃えます。
  • 現行の職業別の値は手調整で、どの式でも完全には再現できません。段階は、まず職業×領域ごとに現行値に最も近いものを機械的に選び、 そこから職業の性格と一貫性で手を入れています（第一領域の表で、習得レベルが現行と一致する行は 10 以下で約 50%、全体で約 40%）。
  • 現行より強くなる・弱くなるのを承知で決めた箇所があります。
    • ハイ=メイジ: 全領域で習得が早まり、消費MP が軽くなります。
    • 赤魔道師: 仙術・自然・カオスなどで、2 冊目までの魔法が早く、軽くなります。
    • レンジャーと魔法戦士の秘術: メイジと同じ値になります。
    • 盗賊: 現行は序盤だけ極端に遅い形で、段階では表せません。序盤の習得が早まります。
    • レンジャーのトランプ: 少し弱くなります（第二領域を −3 に揃えるため）。

終盤の魔法の比較

カオス「魔力の嵐」、暗黒「地獄の劫火」、悪魔「深淵招来」、破邪「神威」は終盤の性能を決めるので、 レベル 50・能力値最大・熟練度最大の条件で、成功率と消費MP を職業ごとに比べた表を別に用意しています。

  • 終盤の 4 魔法: Lv50 時点の成功率と消費MP

移行と互換性

  • 基準表はメイジの現行値と technic_info から機械的に作ります。意図のある例外 （観光客の鑑定、パラディンの啓明、魔獣使いのカード類、習得不可の一覧、赤魔道師の巻数）だけデータに残します。
  • セーブデータの形式は変わりません（魔法は番号で保存）。ただし習得レベルが変わる魔法では、既存のキャラクターで 「忘れた／思い出した」の表示が出ることがあります。
  • 歌・武芸・呪術の technic_info は削除し、読み込み経路を魔法領域と同じにします。
  • スポイラー（職業別魔法表）は、位置で値が違う領域（プリーストの生命・暗黒・悪魔・破邪）について、第一領域用と第二領域用の両方を出す形に変わります。
  • CI の JSON 検査（スキーマと意味検査）、読み込みのテスト、スポイラー出力による新旧の突き合わせを合わせて更新します。
  • 実装は、挙動が変わらないもの（基準表の追加、technic_info の移行、位置つきの引き方、巻数の指定）を先に入れ、値が変わる段階への移行を最後の 1 本にします。
