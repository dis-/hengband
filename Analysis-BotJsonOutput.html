Bot向けJSON出力モード

← 解析 / Analysis

概要

Bot向けJSON出力モードは、起動オプション --bot-json-output[=パス] を付けたときだけ有効になる出力専用の機能で、ゲームがプレイヤーのキー入力を待つ直前にその時点の状況を 1行1JSON（JSON Lines / JSONL） で書き出す。外部プログラム（Bot）がこの行を読んで盤面を把握し、ウィンドウへキーを送り返す、という運用を想定している。

  • 実装は src/bot/bot-json-output.cpp に集約される。JSONLへ書く5つの出力関数に加え、制御サーバの state 応答用に make_bot_json_snapshot() が公開されている。
  • JSONL出力関数は先頭で arg_bot_json_output を確認し、モードが無効なら即 return する。制御サーバからの取得は --bot-json-output なしでも利用できる。いずれもゲーム状態を変更しない読み取り専用機能である。
  • 設計上の中心原則はフェアプレイ：「画面上でプレイヤーが知り得る情報だけを出す」。未知のマス・幻覚中の正体・未鑑定アイテムの数値などは、後述のとおり明示的に伏せられている。

対応する起動オプション自体の位置づけは 起動オプション も参照。

1. 有効化とオプション解析

指定 効果
--bot-json-output モードを有効化。出力先は既定の bot-state.jsonl
--bot-json-output=<path> モードを有効化し、出力先を <path> に変更（= の後が空なら既定のまま）
--bot-json-output=- 出力先を標準出力にする
--bot-json-timing JSONL生成の計測ログを有効化。単独ではJSONL出力を有効化せず、標準出力時には記録しない

保持する変数は src/game-option/runtime-arguments.{h,cpp} の3つ。

  • bool arg_bot_json_output（既定 false）
  • bool arg_bot_json_timing（既定 false）
  • std::string arg_bot_json_output_path（既定 "bot-state.jsonl"）

長オプションの共通部分は parse_runtime_argument() で解釈され、POSIX版とWindows版の双方から利用される。--bot-json-output[=path] のパス処理は各フロントエンド側で行う。

  • POSIX/Unix版：src/main.cpp の長オプション解析経路から共通処理を呼ぶ。
  • Windows版：src/main-win/commandline-win.cpp でワイド文字列を扱い、パスはマルチバイトへ変換して格納する。

Windows版のコマンドライン処理は、このモード追加に伴い次の2点も変わっている。

  • 引数ダンプの出力先が標準出力から標準エラーへ移動した。--bot-json-output=- で標準出力をJSONL専用の出力先として使えるようにするため。
  • -o（オリジナル・キー配置）と -r（ローグライク・キー配置）を認識するようになった。Bot側がキー配置を固定できないと、送るキーの意味が環境依存になってしまうため。

実行時に生成されるファイル（BOT_PLAY セーブファイルと bot-state*.jsonl）はリポジトリ直下に書かれるため、.gitignore に登録されている。

2. 出力タイミング（type の5種類）

スナップショットはプレイヤーが入力を求められる直前にだけ書き出される。フックは5か所で、いずれも「共通スナップショット」を作ってから type を差し替え、専用ブロックを追加する構造になっている。

type 出力関数 フック位置 追加ブロック
player_turn output_bot_json_snapshot process_player() の InputKeyRequestor::request_command() 直前（src/core/player-processor.cpp） なし
store output_bot_json_store_snapshot do_cmd_store() のコマンド入力直前（src/store/cmd-store.cpp） store
character output_bot_json_character_snapshot do_cmd_player_status() の冒頭（src/cmd-visual/cmd-draw.cpp） character
knowledge output_bot_json_knowledge_snapshot do_cmd_knowledge() の各カテゴリ選択時（src/cmd-io/cmd-knowledge.cpp） knowledge
look output_bot_json_look_snapshot do_cmd_look() の target_set() 直前（src/cmd-io/cmd-floor.cpp） look

重要な制約として、出力されるのはコマンド入力待ちの瞬間だけである。-more- 待ちや「はい/いいえ」の確認プロンプトの最中には新しいスナップショットは出ないので、外部Botはそれらを既存のスナップショットとメッセージから推測して処理する必要がある。

同じ共通スナップショットは制御サーバの state リクエストでも取得できる。map: false を指定すると地図生成を省略できる。JSONLの messages は前回出力からの増分だが、state は差分状態を消費せず直近履歴を返す。

3. 共通スナップショットの構造

すべての type に共通する最上位キーは次の通り（make_snapshot()）。

キー 内容
type スナップショット種別（前節の5種）
protocol_version JSONスナップショットの互換性バージョン。最新developは 2
turn ゲームターン（AngbandWorld::game_turn）
player プレイヤーの状態（下表）
floor 現在フロアの情報
progress ダンジョン到達・制覇・クエストなどの進行状況
grid_map 知覚済み地形を圧縮した地図（第4節）。state(map=false) と店内スナップショットでは省略
visible_monsters 直接視認しているモンスター（第5節）
detected_monsters 視線外だが感知しているモンスター（第5節）
messages 前回スナップショット以降に増えたメッセージ（最大32件・古い順）
inventory 持ち物（第6節）
equipment 装備（第6節）

protocol_version は制御サーバの info と全スナップショットで共通である。クライアントは処理前に値を確認し、未対応の版を拒否すること。v1とv2の地図形式には互換性がない。

player

キー 内容
y / x 現在座標
can_see_own_grid / light_radius 自分のマスを視認できるか・現在の光源半径
level / exp レベル・経験値
hp / max_hp / mp / max_mp HP・MP
gold 所持金
speed 加速値（pspeed）
ac 表示上のAC（dis_ac + dis_to_a）
recalling 帰還の巻物が発動待ちか（word_recall != 0）
food_state 満腹度の段階（下記）
food_type 種族の食性（PlayerRace::food()）
class_id / race_id / personality_id 職業・種族・性格のID
skills melee / shooting / saving / device / stealth と、二刀流・盾の熟練度
melee 左右の手の攻撃回数・命中修正・ダメージ修正（表示値）
status blind / confused / afraid / poisoned / stunned / cut / paralyzed / hallucinated
stats 能力値6種それぞれの cur / max / use / index / drained
ability_sources 判明している耐性・能力19種を、equipment / permanent / temporary の供給源別に出力
immunities 炎・冷気・電撃・酸・閃光・暗黒・地獄の免疫を供給源別に出力
vulnerabilities 酸・電撃・炎・冷気・閃光・呪力の弱点を供給源別に出力

food_state は player.food の閾値（src/player/digestion-processor.h）で決まる。

値 条件
fainting food < 500（PY_FOOD_FAINT）
weak < 1000（PY_FOOD_WEAK）
hungry < 2000（PY_FOOD_ALERT）
normal < 10000（PY_FOOD_FULL）
full < 15000（PY_FOOD_MAX）
gorged 15000 以上

ability_sources の各能力は { equipment, permanent, temporary } というオブジェクトである。装備は鑑定済みフラグ（get_flags_known()）、恒久側は種族・職業・変異・性格等（player_flags）、一時側は時限効果と構え（tim_player_flags）。免疫は対応する耐性にも反映される。旧プロトコルの真偽値 abilities は廃止された。

permanent は「絶対に失効しない」という意味ではない。変身中は変身先種族の能力がここに現れる。immunities.nether.permanent は専用フラグではなく、スペクター種族の地獄無効を表す。弱点はキャラクター画面で確認できる範囲に限定され、未表示の呪い特性までは開示しない。

floor

キー 内容
dungeon_id / level ダンジョンIDと階層
feeling 公開済みの階の雰囲気（深度表示色および Ctrl+F で確認できる段階）
width / height フロアの大きさ
inside_arena 闘技場内か
quest_id クエストフロアならそのID
town_id 街ID（town_index - 1。街に居なければ -1）
town_index 内部の街インデックス（街に居なければ 0）
in_town 街のマスに立っているか

in_town は dun_level == 0 && is_in_any_town() で判定している。is_in_any_town()（＝current_town_index > 0）はダンジョンに潜っても解除されないため単独では使えず、また地上でも「街」と「ダンジョン入口だけがある荒野マス」は共に dungeon_id = 0 / level = 0 なので、この2条件の組み合わせが必要になる。

progress

キー 内容
recall_dungeon_id 帰還先ダンジョン
recall_depth 帰還先ダンジョンでの最深到達階（＝帰還したときに降り立つ階）
entered_dungeon_ids 一度でも入ったダンジョンのID一覧
dungeon_recall_depths ダンジョンID（文字列キー）→ 最深到達階
conquered_dungeon_ids 制覇済み（最深部の主が討伐済み）のダンジョンID一覧
yeek_cave_conquered イークの洞穴（列挙名は GALGALS）の制覇状況
angband_recall_unlocked アングバンドへ帰還できるか
visited_town_ids 行き方を知っている街のID一覧
quests 開示対象のクエスト一覧（下記）

angband_recall_unlocked は has_entered() ではなく get_max_level() > 0 で判定する。宿屋で噂を聞くと set_max_level(mindepth) が呼ばれて「アングバンドへ帰還できるようになった」状態になるため、実際に入場していなくても解禁されうるからである。visited_town_ids も同様に、実際に訪れた街と宿屋の噂で行き方を知った街の両方を含み、宿屋の「他の街へテレポート」に並ぶ街と一致する。

quests（make_disclosed_quests_json()）は**「遂行中のクエスト」画面の開示規則をそのまま再現**している。

  • QUEST_FLAG_SILENT のクエストと、遂行中でも完了でも失敗でもないものは出さない。
  • 遂行中のランダムクエストは最も浅い1件だけ（QuestList::find_shallowest_random_quest_id()。アングバンドの到達階層に届いていないもの・複数体討伐のものは開示しない）。
  • 完了/失敗したランダムクエストは、名前を討伐対象モンスター名に差し替えて出す。
  • 種別に応じて r_idx（討伐対象）、cur_num / max_num（討伐数）、reward_artifact_id / reward_baseitem_id（アーティファクト探索の報酬）を追加する。

4. 圧縮マップ情報（grid_map、プロトコルv2）

プロトコルv1の nearby_grids は廃止され、v2ではプレイヤーが現在知覚できる地形観測を palette と行単位のランレングス runs に圧縮して返す。地形の可視判定は通常の画面描画と is_map_terrain_visible() を共有し、盲目・暗視・モンスターの暗闇・壁の表示設定なども画面と同じになる。

観測できないセルは runs から省略される。これは「床ではない」「過去の記憶が誤り」という意味ではなく、今回のスナップショットでは新しい地形観測がないという意味である。クライアントはフロア単位で過去の観測を保持し、同じセルを再観測したときに更新する必要がある。

grid_map の構造。

キー 内容
w / h フロアの幅・高さ。座標はゼロ起点の y, x
palette [terrain_id, flag_bits, terrain_bits, known] の配列。地形はMIMIC（見かけ）を使い、秘密ドア等の正体は出さない。現在の flag_bits は予約値0、known は1
runs [y, x0, length, palette_index]。同じ行で同じパレット値が連続するセルだけをまとめる
cells y, x と追加情報を持つ疎な配列。短いキーは m=モンスターindex、o=発見済みオブジェクトのスタック数、t=tval配列、s=店、e=ダンジョン入口、q=クエスト、b/p=建物種別/special
found_items [y, x, stack_count, tval, ...]。地形が今回見えなくても検知済みの品を出す。金貨・未発見品・個数0は除外し、幻覚中はtvalを0にする
unsafe_rows 地下かつ罠未調査表示が有効な場合だけ、高さと同数の16進文字列。それ以外は null。各ニブルの下位ビットからx座標を表す

terrain_bits は次の順にビット0から割り当てられる：building, can_dig, door, down_stairs, entrance, floor, has_gold, los, move, permanent, quest_enter, quest_exit, stairs, store, trap, tunnel, up_stairs, wall。内部の CAVE_MARK / CAVE_KNOWN / 照明等は公開しない。

追加キー 条件
s 店の入口（どの店かを示す StoreSaleType）
e ダンジョン入口（grid.special）
q クエストの入口・出口
b / p 施設（建物）タイル

cells.t を幻覚中に空配列にし、found_items のtvalを0にする一方で、スタック数と行長は保つ。「そこに何かがあることは分かるが種類は分からない」という画面の見え方に合わせた仕様である。

5. モンスターの3系統

モンスター情報はわざと3通りの異なる可視判定で出力される（統合してはいけない、とソースにコメントがある）。

出力先 判定条件 用途
visible_monsters ml かつそのマスが視線内 直接視認しているものだけ。常時出力
detected_monsters ml かつ視線外 ESP・探知で見えているもの。y / x / esp / detected が付く
look の monster ml のみ look コマンド自身の判定（target_set_accept）と一致させる

各モンスターの内容は index / y / x / race_id / name / health / asleep / stunned / confused / fearful / friendly / pet。地図を省略した state(map=false) でも位置を取得できる。health は割合の帯で出す。

値 残りHP
unhurt 満タン
lightly_wounded 60% 以上
wounded 25% 以上
badly_wounded 10% 以上
almost_dead 10% 未満

幻覚中は index / y / x / hallucinated / pet だけになり、正体・HP帯・状態異常は伏せられる。幻覚中でも「そのマスに何かがいる」ことは画面のランダムシンボルで分かるため、伏せるのは正体の方だけという切り分けになっている。

6. アイテムの表現（make_item_json）

持ち物・装備・床のアイテム・我が家の在庫まで、すべてこの共通関数を通る。鑑定状態に応じて出るフィールドが増えるのがポイント。

条件 フィールド
常に name（describe_flavor の表示名）・count・tval・aware・known・fully_known・is_equipment・weight・is_bounty・inscription
「未知の匂い/形」を判別済み（aware） sval
擬似鑑定済み（IdentificationFlag::SENSE） pseudo_feeling（broken / terrible / worthless / cursed / uncursed / average / good / excellent / special / none）
鑑定済み（known） charges / pval / fuel / timeout / is_ego / is_artifact / is_cursed / is_broken / to_h / to_d / to_a / ac / damage_dice / known_flags（フラグIDの配列）。武器・弓なら weapon_proficiency（その武器種の熟練度）

未鑑定のアイテムから充填回数や修正値が読めないのは、通常プレイのアイテム説明と同じ制約である。inscription はプレイヤー自身が書いた銘なので開示され、外部Botにとってはセーブファイルに永続する唯一の自前メモ領域として使える。

スロット表記は inventory が持ち物欄の記号（a, b, …）、equipment がラベル（main_hand / sub_hand / bow / main_ring / sub_ring / neck / light / body / outer / head / arms / feet）。

7. store ブロック（店の中）

店のコマンド入力待ちで、共通スナップショットに store が付く。店内では移動できず地形も変わらないため、直前の地上スナップショットと同一になる grid_map は省略される。

  • store_type … 店種別（StoreSaleType）。
  • stock_num … 店の全在庫数。
  • page_top / page_size … 現在ページの開始位置と1ページの枠数。満杯のページでも次ページの有無を正しく判断できる。
  • items[] … 在庫。letter は現在表示中のページを基準にした相対記号（store_top の商品が a）で、ページ外の在庫は出力しない。店側が受け付ける入力と一致させるための仕様。
  • 通常の店では商品を完全鑑定済みとして共通アイテムJSONを作り、name（OD_STORE 表記）と price（price_item による実売価格）を加える。特性・修正値・充填回数も店頭で公開される範囲として出力する。
  • 我が家・博物館は売買ではないので価格を出さず、通常のアイテムJSON（第6節）をそのまま並べる。

8. character ブロック（C キー）

キャラクター情報画面を開いた瞬間に出る、詳細ステータス一式。

キー 内容
skills thn / thb / sav / dev / stl / dis / srh / fos / dig の生値
ranged to_h_b / shots / shot_frac / shooting_multiplier / see_infra
melee expected_damage_x100（左右の手の期待ダメージ×100）・expected_damage_per_round_x100（攻撃回数を掛けたもの）・bare_hand / two_handed / monk_stance
stats 能力値ごとの top / maximum / at_maximum
age / height / weight / social_class / alignment 身上・属性値
realms 使用魔法領域（ID＋名称）
chaos_patron カオスパトロン
mutations 保有する突然変異IDの配列
characteristics 耐性・能力フラグ表（下記）

characteristics はキャラクター画面の耐性表そのもので、136種のフラグについて次を出力する。

  • flag_id … tr_type のID。
  • equipment[] … 装備スロットごとの { slot, has }。鑑定済みフラグのみ（get_flags_known()）。
  • player / temporary … 内在フラグ／一時効果。
  • immunity / temporary_immunity / vulnerability … 免疫・一時免疫・弱点。

stats の maximum（能力値の上限）は、KNOW_STAT を得ているか既に上限に達している場合のみ数値を出し、それ以外は null になる。ここも画面表示（? 表示になる）と同じ扱い。期待ダメージと射撃性能は、表示用の calc_player_two_hands() / calc_player_shot_params() を再利用して算出している（この2関数はBot出力のために src/view/status-first-page.h へ公開された）。

9. knowledge ブロック（~ の知識メニュー）

知識メニューでカテゴリを選ぶと、その内容がJSONでも出る。category（スラッグ）と menu_key（選択に使ったキー）が必ず付く。

キー category 内容キー

8 bounty today（本日の賞金首。未確認なら null）・wanted（未達成の賞金首）

6（モンスターの思い出）と 7（撃破数）はJSON出力の対象外。spell_exp では剣術（HISSATSU）だけ exp と rank が null になり masked: true が付く。剣術は熟練度の概念が画面上も表示されないためで、これも画面と出力を一致させる措置である。

10. look ブロック（l / x の周辺確認）

look コマンドの巡回対象（target_set_prepare(TARGET_LOOK)）をそのままの順序で配列にしたもの。

  • hallucinated … 幻覚中フラグ。
  • panel … 現在の表示パネル範囲（row_min / row_max / col_min / col_max）。
  • grids[] … index（巡回順）・y / x・distance・is_player_position・terrain・monster・items[]・carried_items[]（モンスターが持っているアイテム）。

地形は、マーク済みでもなく player_can_see_bold() でもないマスでは TerrainTag::NONE に差し替えられ、redacted: true が付く。look で「何かが見えているが地形は分からない」状況を再現するための伏せ字である。

11. 出力ファイルの扱い

項目 仕様
既定の出力先 bot-state.jsonl（--bot-json-output=- なら標準出力）
形式 JSON Lines。1スナップショット＝1行、書き込みごとに flush
セッション開始時 ファイルを truncate して開き直す（過去実行分は残さない）
サイズ上限 BOT_JSON_OUTPUT_MAX_BYTES = 256MiB。超えたら再度 truncate して書き直す
文字コード sys_to_utf8() でUTF-8化。変換失敗時は <encoding-error>、dump() も error_handler_t::replace
open失敗 JSONLファイルのopenに2回連続で失敗すると標準エラーへ通知し、その実行中のJSONL出力を停止。成功時に失敗回数をリセット

全マップを含むスナップショットは大きいため、履歴を貯めずに最新行だけを消費する前提で上限打ち切りにしている。Bot側はファイルが縮んだことを検知して先頭から読み直せばよい。

messages の作り方にも状態がある（make_recent_messages_json()）。

  • 前回スナップショット時のメッセージ総数と最新行を静的に保持し、増分だけを古い順に出す。
  • 総数が同じでも最新行の内容が変わっていれば1件だけ出す（同じ行がまとめられた場合の取りこぼし防止）。
  • 1回のスナップショットで最大 BOT_JSON_MAX_MESSAGES = 32件。
  • 最初の呼び出しは基準値を取るだけで空配列を返す。

任意の計測ログ（--bot-json-timing）

ファイル出力時だけ、JSONLパスへ .timing.log を付けたファイルに type / turn / build_us / dump_us / write_us / bytes を1行ずつ記録する。既定は無効で、標準出力と制御サーバの state は対象外。

  • 10MiBに達した次の書込時にローテーションし、.1（最新）〜.3 の3世代を保持する。
  • 起動時は現在ログを空にするがバックアップは残す。旧名 emitter-timing-c2.log は移行・削除しない。
  • シンボリックリンク、複数ハードリンク、通常ファイル以外、JSONL本体と同一実体のパスは拒否する。
  • 計測ログの回転・書込に失敗した場合は計測だけを停止し、JSONL出力とゲームは継続する。

12. フェアプレイ設計のまとめ

このモードは「Botに有利な情報を足す」のではなく「プレイヤーが画面から読める情報だけを機械可読にする」ことを目的としており、次の伏せ字が入っている。

  • 知覚できない地形は grid_map.runs に出さない。欠落は今回の観測なしを意味し、クライアント側の過去観測を自動的に否定しない。
  • 内部の地形状態フラグは出さず、画面に現れるMIMIC地形と静的な地形特性だけを出す。
  • 幻覚中はモンスターの正体・HP帯・状態異常、床のアイテムの種類を伏せる。位置と個数は伏せない。
  • 未鑑定アイテムの充填回数・修正値・ダイス・フラグは出さない。未判別なら sval すら出さない。
  • 能力値の上限は KNOW_STAT、命の格付けは KNOW_HPRATE を得ているときだけ。
  • クエストは「遂行中のクエスト」画面の開示規則（沈黙クエスト非表示・遂行中ランダムクエストは最も浅い1件のみ）に従う。
  • 剣術の熟練度は画面同様マスクする。
  • 直接視認・感知・lookでモンスターの可視判定を分けており、常時出力の visible_monsters にはESPで見えているだけの相手を混ぜない。
  • 店の在庫記号は実際に押せるページ相対の記号だけを出す。

一方で、inscription（プレイヤーが書いた銘）、制覇済みダンジョン、帰還可能階層、行き方を知っている街など、キャラクター画面や宿屋のメニューで確認できる情報は開示する。

まとめ

  • --bot-json-output[=パス] を付けたときだけ有効な、読み取り専用のJSONL出力モード。無効時のコストは分岐1つ。
  • 出力タイミングは入力待ちの直前の5か所（通常ターン・店・キャラクター情報・知識メニュー・look）。共通スナップショットに種別ごとのブロックが加わる。
  • 最新developのプロトコルはv2。nearby_grids を廃止し、パレット＋ランレングス方式の grid_map に置き換えた。
  • 共通スナップショットには、供給源別の能力・免疫・弱点、フロア、進行状況、圧縮地図、可視/感知モンスター、メッセージ、持ち物、装備が入る。
  • 同じスキーマは制御サーバの state でも取得でき、地図を省略可能。JSONLの増分メッセージ状態とは分離されている。
  • すべての開示範囲は「画面で見える情報」に揃えられており、未知・幻覚・未鑑定・未取得の知識は明示的に伏せられる。
